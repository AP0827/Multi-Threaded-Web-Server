MTWS - MULTITHREADED SECURE HTTP SERVER
Consolidated Requirements for Academic Submission
May 2026

==============================================
1. PROJECT OVERVIEW
==============================================

MTWS is an educational HTTP/1.1 server implemented in Go, designed to demonstrate network
security concepts and HTTP compliance through:
● Custom HTTP/1.1 parser with strict RFC 7230-7231 compliance
● Web Application Firewall (WAF) with signature-based threat detection
● Per-IP token bucket rate limiting for DoS protection
● Worker pool concurrency with buffered job queue architecture
● Side-by-side security benchmarking against nginx + ModSecurity
● Load testing and performance metrics collection

Target Deployment: Single-machine classroom labs, security research, educational demonstrations.

4. FUNCTIONAL REQUIREMENTS
==============================================

4.1 CORE HTTP SERVER

FR-2.1: TCP Connection Acceptance
- Accept incoming TCP connections on configurable port (default 8080)
- Status: Implemented

FR-2.2: HTTP/1.1 Request Parsing
- Parse request line, headers, body (Content-Length and chunked transfer encoding)
- Strict compliance: reject ambiguous requests (no folded headers, no duplicate headers)
- Size limits: request line 4096 bytes, header line 8192 bytes, max 64 headers, body 1 MiB
- Fail-closed: return 400 Bad Request on any ambiguity
- Status: Implemented

FR-2.3: HTTP Response Generation
- Generate responses with status codes (200 OK, 400 Bad Request, 403 Forbidden, 404 Not Found, 500 Internal Server Error)
- Include headers (Content-Type, Content-Length, Date) and body
- Status: Implemented

FR-2.4: Request Routing
- Exact path matching to registered handlers
- 404 response if path not found
- Status: Implemented

FR-2.5: Connection Closure
- Close socket after response
- Clean up resources
- Status: Implemented


4.2 CONCURRENCY & JOB QUEUE

FR-3.1: Worker Pool Architecture
- Fixed-size pool of goroutines (default 10 workers)
- Buffered job queue (default capacity 200)
- Workers block on empty queue; listener blocks when queue full (natural backpressure)
- Status: Implemented

FR-3.2: Connection-to-Job Dispatch
- Listener accepts connection, extracts client IP
- Rate limiter decision
- If allowed: post Job to queue
- If denied: close connection immediately
- Status: Implemented


4.3 SECURITY & RATE LIMITING

FR-4.1: Per-IP Rate Limiting (Token Bucket)
- One token bucket per unique client IP
- Configurable refill rate (default 5.0 tokens/sec) and capacity (default 10.0 tokens)
- If tokens ≥ 1: deduct 1, allow request
- Else: deny, close connection
- Disable via MTWS_RATE_LIMIT_DISABLED or MTWS_BENCHMARK_MODE
- Status: Implemented

FR-4.2: WAF (Web Application Firewall) Rule Matching
- Aho-Corasick automaton for pattern matching
- Policy file: one signature per line (default: security/waf/default-policy.txt)
- Scans: request URI, header names/values, body, trailers
- Match → SecurityError → 403 Forbidden + security log
- Status: Implemented

FR-4.3: Malformed Request Rejection
- Detect and reject invalid syntax, duplicate headers, invalid chunks, missing Host header
- Response: 400 Bad Request
- Status: Implemented

FR-4.4: Connection Timeout
- Read deadline: 5 seconds (anti-Slowloris)
- On timeout: close connection, log event
- Status: Implemented

6. DATA FLOW & ARCHITECTURE
==============================================

REQUEST FLOW:

1. Listener accepts TCP connection → extract client IP
2. Rate Limiter (token bucket) → Allow or Deny
3. If Allowed → Post Job{connection, router} to buffered queue (capacity 200)
4. If Denied → Close connection immediately
5. Worker Pool (10 workers) reads from queue
   - Each worker calls HandleConnection(conn, router)
6. Connection Handler:
   - Set 5-second read deadline
   - Parse HTTP/1.1 request via bufio reader
   - WAF scans all fields (URI, headers, body, trailers)
   - If malicious pattern → 403 Forbidden + security log
   - If parse error → 400 Bad Request
7. Router Dispatch:
   - Extract request path
   - Lookup handler (exact path match)
   - If not found → 404 Not Found
   - If found → execute handler
8. Response Writer:
   - Buffer status + headers
   - Write body
   - Flush to socket
9. Connection Close:
   - Clean up resources
   - Worker ready for next job

QUEUING MECHANICS:
- Listener blocks when queue full (backpressure)
- Workers block when queue empty
- Natural flow control without explicit synchronization
- Bounded goroutines: listener (1) + workers (10) + job queue
